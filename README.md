<h1 align="center">ChatGPT 额度助手</h1>

<p align="center">在 macOS 菜单栏查看 Work / Codex 剩余额度与重置时间。</p>

<p align="center">macOS 14+ · Swift 6+ · 无第三方依赖 · MIT</p>

ChatGPT 运行时，菜单栏显示 `GPT 61%`；点击可查看各额度窗口及重置倒计时。退出 ChatGPT 后，菜单栏项目自动隐藏，助手在后台等待下次启动。

> 显示的是 Work / Codex 的额度窗口，不是普通聊天的消息计数，也不是 API 余额。根据 [OpenAI 官方说明](https://learn.chatgpt.com/docs/pricing)，ChatGPT Work 与 Codex 共用额度；实际可用窗口以账号服务返回的数据为准。

## 功能

- 显示服务返回的多个额度窗口，包括窗口时长、剩余百分比和重置时间。
- 菜单栏显示所有有效窗口中最低的剩余百分比。
- 面板中实时显示各会话已用的 token：可自动跟随最新会话或选择具体会话，同一会话使用多个模型时按模型拆分。
- 会话统计直接读取本机 Codex 会话记录，不联网、不增加第三方依赖。
- 额度窗口空出时自动发送一次「你好」并归档，把 5 小时/每周窗口的重置时间固定在发送时刻。
- 每 60 秒刷新额度；打开面板、切回 ChatGPT、唤醒电脑及收到额度通知时也会请求更新。
- ChatGPT 退出后，若最近 1 小时有会话活动或「自动固定刷新时间」已开启，菜单栏仍保留。
- 支持登录 macOS 时启动，无 Dock 图标。
- 读取失败时清空旧数字；数据超过两分钟未更新时标记过期。

## 使用条件

- macOS 14 或更新版本。
- 已安装并登录带有内置 Codex App Server 的 ChatGPT 桌面端；仅安装普通聊天版不一定满足条件。
- 账号服务能够返回可用的额度窗口；只使用 API Key 的场景不在本项目支持范围内。
- 读取额度时需要网络连接。

目前验证环境为 Apple Silicon，详见 [验证记录](VALIDATION.md)。Intel 与其他桌面端版本的兼容性尚未完成验证。

## 安装与启动

### 从源码构建

安装 Swift 6.0+ 和匹配的 macOS SDK（Xcode 或 Xcode Command Line Tools）。在项目根目录执行：

```sh
./scripts/test.sh
./scripts/build.sh
```

构建结果为 `dist/ChatGPT额度助手.app`。

### 使用应用

1. 将构建得到的 `ChatGPT额度助手.app` 拖到“应用程序”文件夹。
2. 打开 ChatGPT 并登录账号，再双击额度助手。
3. 点击菜单栏的 `GPT …` 查看各窗口的额度。
4. 如需随系统启动，勾选面板中的“登录 macOS 时启动”。

仓库若提供 Release 安装包，请按对应版本的说明下载和安装。默认构建采用本地 ad-hoc 签名，**未经 Apple 公证**；从互联网下载后可能被 macOS 拦截。确认来源后，可按 [Apple 的应用打开说明](https://support.apple.com/zh-cn/102445) 处理，或自行从源码构建。

## 显示规则

| 项目 | 行为 |
| --- | --- |
| 剩余百分比 | `100 − usedPercent`，限制在 0–100；界面四舍五入为整数 |
| 菜单栏数字 | 所有有效窗口的最低剩余值 |
| 窗口名称 | 根据服务返回的实际时长生成，不固定假设主窗口是 5 小时 |
| 缺少字段 | 缺少有效用量的窗口不显示；时长或重置时间缺失时标记未知 |
| 数据过期 | 超过两分钟未更新后，菜单栏显示 `GPT —`，面板提示过期 |
| 重置时间已到 | 等待服务重新确认，不自行把额度改为 100% |

服务端统计延迟、其他客户端的使用和网络状况都会影响更新时效。面板中的倒计时随界面更新，不是逐秒计时器。

## 会话 Token 统计

面板下半部分读取本机 Codex 会话记录（默认 `~/.codex/sessions`，遵循 `CODEX_HOME`），实时显示每个会话已用的 token：

- 「自动跟随最新」跟随最近写入的会话；也可以在下拉框中选择具体会话。
- 同一会话使用多个模型时，按模型分别列出总量与占比。
- 子代理会话计入其父会话，并标注数量。
- 面板打开时每 2 秒读取新增内容并重扫会话列表；面板关闭后每 20 秒刷新一次。

统计口径：

| 项目 | 行为 |
| --- | --- |
| 总计 | 输入 + 输出，等于服务返回的 `total_tokens` |
| 缓存输入 | 已包含在输入中，不重复计入总计 |
| 推理 | 已包含在输出中，不重复计入总计 |
| 数据来源 | 本机逐响应 `token_usage_record`；旧格式回退到累计 `token_count` |
| 已归档会话 | `archived_sessions/` 下的记录不在统计范围，面板会提示数量 |
| 普通 ChatGPT 聊天 | 不产生本地 token 记录，不在统计范围 |

订阅额度是服务端按窗口计算的百分比，与本地原始 token 数不是同一口径：缓存命中的输入同样计入 token，但不代表等量的额度消耗。面板数字用于观察用量趋势，不能换算成额度百分比。

## 自动固定刷新时间

额度窗口在**没有任何用量**时，服务端返回的重置时间会随当前时间滑动（实测两次相隔 72 秒读取，`resetsAt` 始终等于「当前时间 + 窗口时长」）。发送一次消息后，窗口被锚定，重置时间固定为「发送时刻 + 窗口时长」。

开启「窗口空出时自动发『你好』」后：

- 5 小时窗口每次空出、每周窗口每次整体清零时，应用会新建一个 Codex 会话、发送「你好」、随即归档该会话。
- 每次约消耗 1–3 万 token（实测一次 23,820 tokens），计入 5 小时和每周额度。
- 只对 5 小时（300 分钟）和每周（10080 分钟）的 Codex 窗口生效，其他额度桶不触发。
- 默认开启，可在面板随时关闭；发送失败按 1 / 5 / 15 / 30 分钟退避重试，最多 10 次。
- 电脑睡眠或应用未运行时不会发送；唤醒/启动后如果窗口仍然空着，会补发一次，周期从补发时刻重新固定。
- 归档失败时会话可能留在 Codex 列表中，可在 Codex 中手动归档。

> 每周额度只有在整体清零时才会空出；如果周窗口仍有历史用量，发送「你好」不会改变它的重置时间。面板「上次」一行会记录每次发送的结果与用量。

## 隐私与工作方式

助手启动 ChatGPT 自带的 `codex app-server --stdio`，通过本地 JSON-RPC 通信，只发送 `initialize`、`initialized` 和 `account/rateLimits/read`。协议见 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

助手本身不读取或复制登录令牌，不读取聊天内容；除开启「自动固定刷新时间」时发送一次「你好」外，不创建聊天、不运行模型任务；没有遥测与自建服务器。内置服务负责身份认证、凭证更新及与 OpenAI 服务通信，也可能维护自己的本地运行数据。

会话统计只读取本机 `~/.codex` 下的会话记录，提取 token 计数、模型名、会话标题与工作目录；不读取或保存消息正文，不发送到任何服务器。

自动发送通过本机 Codex CLI 执行一次模型回合（新建会话 → 发送「你好」→ 归档），这是应用唯一会主动运行模型的功能，可在面板关闭。

图标为独立设计的额度仪表图案。本项目与 OpenAI 无隶属或官方合作关系。

## 常见问题

**打开后没有图标？** 助手在 ChatGPT 运行、最近 1 小时有会话活动，或「自动固定刷新时间」开启时显示菜单栏项目；菜单栏过满时系统会把它收进隐藏区。它没有 Dock 图标；隐藏期间可通过“活动监视器”找到 `QuotaCompanion` 并退出。

**提示找不到内置服务？** 更新 ChatGPT 桌面端，并确认所用版本带有 Codex 服务。当前适配的二进制位置见 [开发说明](CONTRIBUTING.md)，应用升级后路径可能变化。

**提示登录或读取失败？** 在 ChatGPT / Codex 中确认账号登录状态，检查网络，再点击“刷新”。读取失败时不会继续展示旧额度。

**自动发送会不会一直发？** 不会。窗口只有在空出（没有用量）时才会触发，发送后窗口变成非空，直到下一次空出；失败最多重试 10 次，之后等窗口再次出现用量或应用重启。

**为什么 5 小时重置时间会变？** 窗口没有用量时，服务端返回的重置时间是滑动的；发送一次「你好」后才会固定下来。开启自动发送即可让周期稳定。

**为什么面板里的 token 数和额度页对不上？** 额度页是服务端按窗口权重算出的百分比；面板是服务端返回的原始 token 计数，缓存输入与推理 token 都包含在内，两者口径不同。

**无法设置开机启动？** 先将 app 放入“应用程序”文件夹，再设置；必要时在“系统设置 → 通用 → 登录项”中允许启动。
